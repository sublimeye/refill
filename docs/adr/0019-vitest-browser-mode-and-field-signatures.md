# ADR 0019: Vitest browser mode (Playwright provider) for DOM tests; field signature rules (`idStable`, bounded `labelText`)

## Context
Field signatures (spec 5.1) and, later, the eligibility check, matcher and fill engine read real DOM: `label[for]`, `closest("label")`, `aria-labelledby`, `checkVisibility`, `elementFromPoint`, and React/Vue controlled-input behavior. jsdom/happy-dom do not implement layout, visibility or focus faithfully, so tests of that code in Node would assert against a fake. The e2e suite (Playwright with the built extension) is too slow and coarse for per-rule cases.

## Decision
- Vitest 5.0.5 browser mode with the official Playwright provider: `@vitest/browser-playwright` 5.0.5 and `@vitest/browser` 5.0.5, both pinned exactly. Real Chromium (the same Playwright 1.64.1 download CI already installs), headless.
- A separate config, `vitest.browser.config.ts`, includes only `tests/browser/**/*.test.ts`; script `pnpm test:browser`. `vitest.config.ts` still includes only `tests/unit/**`, so `pnpm test` stays Node-only and never needs a browser.
- CI: the "Install Playwright Chromium" step moves before the unit/browser test steps, and `verify` gains a `test:browser` step with `timeout-minutes: 5`.
- `react` 19.3.1, `react-dom` 19.3.1 and `vue` 3.5.44 (latest stable, exact) are added as devDependencies now. They are used from Task 10 to test fills into framework-controlled inputs. They are test-only: nothing under `src/` imports them. Check recorded for Task 10 onward: after `pnpm build`, `grep -rlw -e react -e react-dom -e vue .output/chrome-mv3` must find nothing, and a search for framework internals (`ReactCurrentDispatcher`, `__VUE_OPTIONS_API__`, `createVNode`) must find nothing. Verified at this commit (no imports yet): clean.
- `src/lib/fields/signature.ts` is DOM-only with zero runtime dependencies (it runs in the content script).
- `idStable` returns null for: empty or longer than 256; a run of >= 4 digits; a React id token anywhere in the id (`:r1:`, `«r1»`, `:R2a6:`, as in shadcn `:r1:-form-item` and `radix-:r1:`), or the React 19.2+ `_r_1_` / `_R_1ab_` form (preceded by start or a non-alphanumeric); a known generated prefix (`radix-`, `headlessui-`, `react-select-`, `ember<n>`, `j_idt<n>`); sequential `/^[a-z][\w-]*[-_]\d+$/i`; >= 3 `-`/`_` separated hex groups (>= 3 chars, digits and letters mixed) such as `user-a8f3-c9e2-1b7d-44e0`; or a hash-like token. The token rule is refined from the brief's "a run of >= 12 chars from `[A-Za-z0-9_-]` with letters and digits": a token is a maximal `[A-Za-z0-9]` run (`-` and `_` separate words) and is hash-like when >= 12 chars with letters and digits mixed, ignoring up to 3 trailing digits for the mix test. The literal rule marked `billing_address_line1` (21 chars, letters plus `1`) and `ctl00_Main_Acct` as generated, which would drop good evidence on most real forms. Stable on purpose: `email`, `account-number`, `billing_address_line1`, `ctl00_ContentPlaceHolder1_txtAmount`, Rails `user_address_attributes_0_line1` (positional index separates line1 from line2). Consequence of the sequential rule: `shipping-address-line-2` and `emergency_contact_phone_1` are also unstable (spec lists `<prefix>-<n>`).
- `nameIdDerived`: equal after `$` to `_` (ASP.NET), `a[b][c]` to `a_b_c` (Rails/PHP), or case-insensitively. Computed from the full, uncapped values.
- `labelText` is bounded because page content is hostile. Sources in order `label[for]`, wrapping `<label>`, `aria-labelledby`, `aria-label`, `placeholder`; labels come from the control's `labels` list (the browser's own association, so duplicate ids resolve correctly), with a `label[for="<CSS.escape(id)>"]` lookup only for non-labelable controls (`labels` is null). Text is collected iteratively (no recursion depth limit) under a budget of 2 000 nodes and 1 024 raw characters per source; `aria-labelledby` reads at most 16 ids sharing one budget; at most 16 `label[for]` labels. Nested form controls, `script`, `style`, `template`, `noscript` and `[hidden]` subtrees are skipped. Then normalize (lowercase, collapse whitespace, trim, strip trailing `*`/`:` repeatedly) and truncate to 256.
- `buildSignature` never throws on a hostile DOM: if label collection throws, `labelText` is null for that field. Every string in `Sig` is <= 256 (`name`, `autocomplete`, `formAction` truncated; `idStable` null when the id is longer), so a page cannot push a message over the content-message caps; this module owns that cap.
- Vitest failure screenshots are off (`screenshotFailures: false`) and `.vitest/` is git-ignored; `passWithNoTests` is not set for browser mode, so a broken `include` glob fails CI.

## Consequences
- Browser tests run Chromium once more in `verify` (a few seconds for the signature suite); the 5-minute step cap bounds a stall.
- Two Vitest configs to keep in step on shared settings (currently none shared).
- A random id that is short, or whose digits are only a 1-3 digit suffix on a 12+ letter run, is kept as stable. It then simply fails to match on the next load; the other evidence (name, label, autocomplete) still decides.
- Hidden text is skipped only via the `hidden` attribute, not computed style (`display:none` via CSS still counts); deterministic per site, so it does not hurt matching.
- Test fixtures use `innerHTML`; the Semgrep ban applies to `src/` only (rules are path-scoped), and test files are the one place it is acceptable.

## Status
Accepted.
